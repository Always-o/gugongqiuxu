# 环境配置说明

本文档是仓库的环境配置总说明，覆盖「本地运行」「环境变量」「依赖」「线上部署」「排错」五部分。
相关文件：`.env.example`、`package.json`、`scripts/serve.mjs`、`docs/依赖清单.md`。

---

## 1. 运行环境要求

本项目是**纯静态前端站点**，没有后端服务、没有数据库、没有构建步骤、没有第三方 API。

| 项目 | 最低要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10 / macOS 10.15 / 任意 Linux | 无平台相关代码 |
| 浏览器 | Chrome 90+ / Edge 90+（推荐） | 语音识别仅 Chromium 系支持 |
| Node.js | >= 18 | **仅**用于 `npm start` 本地预览服务；不装也能运行 |
| Python | >= 3.8（可选） | 替代 Node 的第二种本地预览方式 |
| Git | 任意较新版本 | 仅用于克隆与提交 |
| 网络 | 不需要 | 页面无任何 CDN / 外部字体 / 远程图片 / 统计脚本，断网可跑 |

> 直接双击 `index.html` 用 `file://` 打开也能跑通绝大多数功能；只有浏览器语音识别在该协议下可能受限，改用本地 http 服务即可。

## 2. 环境变量

### 2.1 有没有必填变量？

**没有。** 网页代码不读取任何环境变量，仓库里也不存在需要保密的密钥、Token 或 API 地址。
这是零依赖纯前端项目的正常状态，也是「照片不上传、断网可用」的前提。

### 2.2 模板与用法

模板文件：`.env.example`。复制为 `.env` 后按需修改：

```bash
cp .env.example .env
```

`.env` 已被 `.gitignore` 排除，**不要提交**到公开仓库。不复制 `.env` 也能直接 `npm start`，脚本会使用默认值，并优先采用命令行里显式设置的变量：

```bash
PORT=9000 npm start        # 临时换端口，不改 .env
```

### 2.3 变量对照表

| 变量 | 默认值 | 作用 | 被谁读取 |
| --- | --- | --- | --- |
| `PORT` | `8788` | 本地预览服务端口 | `scripts/serve.mjs` |
| `HOST` | `127.0.0.1` | 监听地址；同一局域网演示可改 `0.0.0.0` | `scripts/serve.mjs` |
| `SITE_ROOT` | `.` | 静态文件根目录，相对仓库根目录解析 | `scripts/serve.mjs` |

`scripts/serve.mjs` 内置一个极简 `.env` 解析器（仅标准库）：忽略注释与空行、去掉成对引号、不覆盖已存在的进程环境变量。端口取值非法时自动回退到 8788；`SITE_ROOT` 若指向仓库外则回退到仓库根目录。

## 3. 安装与运行

**无需 `npm install`**（`package.json` 里 `dependencies` 与 `devDependencies` 均为空）。

```bash
git clone https://github.com/Always-o/gugongqiuxu.git
cd gugongqiuxu
npm start                 # 方式一：Node 内置静态服务
# 或
python3 -m http.server 8788 --bind 127.0.0.1   # 方式二：Python
# 或
# 直接双击 index.html                          # 方式三：file://
```

打开 <http://127.0.0.1:8788/>。

语法自检（不需要安装 ESLint 等工具）：

```bash
npm run check             # 对 serve.mjs 与四个 js 文件逐个执行 node --check
```

完整手工验收清单见 README「运行自检」。

## 4. 线上部署（GitHub Pages）

当前仓库已启用 Pages，地址 <https://always-o.github.io/gugongqiuxu/>。

部署要点：

1. 站点文件放在 `main` 分支**根目录**（`index.html` 在根，不是 `docs/` 也不是 `dist/`）。
2. 根目录的 `.nojekyll` 告诉 Pages 跳过 Jekyll 构建，避免以 `_` 开头的目录或文件被误处理——本项目虽无此类目录，保留该文件可确保静态资源原样发布。
3. 仓库 Settings → Pages → Build and deployment → Source 选 **Deploy from a branch**，Branch 选 `main` / `root`。
4. 推送后约 1–2 分钟生效，可用下面命令核对线上与本地一致：

```bash
for f in index.html css/style.css js/data.js js/scene.js js/ai.js js/app.js; do
  printf '%-20s ' "$f"
  curl -s "https://always-o.github.io/gugongqiuxu/$f" | shasum -a 256 | cut -c1-12
  printf '%-20s ' '  local'
  shasum -a 256 "$f" | cut -c1-12
done
```

> Pages 只负责托管静态文件，不需要配置任何环境变量或构建密钥。

## 5. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 端口被占用 | 8788 已被其他进程使用 | `PORT=9000 npm start`，或先关掉占用进程 |
| 语音输入点不动 | 浏览器不支持 `SpeechRecognition`，或用了 `file://` | 换 Chrome/Edge，并用 `npm start` 以 http 打开；页面会自动降级为文字输入 |
| 没有声音 / 朗读无反应 | 系统静音或浏览器未授权音频 | 检查系统音量；朗读依赖 `speechSynthesis` |
| 上传图片后没反应 | 图片体积过大或格式不受浏览器解码支持 | 换 JPG/PNG 小图重试；图片全程只在本地 Canvas 处理 |
| 改了代码刷新没变化 | 浏览器缓存 | 预览服务已设 `Cache-Control: no-store`；若用其他服务器请强制刷新 |
| 手机上排版错乱 | 视口缩放 | 页面已含 `viewport` meta；请用在「浏览器兼容」表内的移动端浏览器 |
| `npm start` 报 Node 版本错误 | Node < 18 | 升级 Node，或改用 Python / 直接打开 HTML |
