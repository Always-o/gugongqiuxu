# 代码规范

本仓库为原生 HTML / CSS / JavaScript 项目，无框架、无构建链。规范的目标是：**评审能直接读源码、改一处不影响全局、断网也能跑**。

---

## 1. 目录职责

| 路径 | 只允许放什么 | 不应该出现什么 |
| --- | --- | --- |
| `index.html` | 页面语义结构、`<script>` 加载顺序 | 业务逻辑、内联脚本、内联样式 |
| `css/style.css` | 设计令牌、版式、组件、动效、媒体查询 | JS、外部 `@import` |
| `js/data.js` | 全部文案与结构化内容（`window.DATA`） | DOM 操作、算法 |
| `js/scene.js` | SVG 程序化场景生成（`window.Scene`） | 业务逻辑、文案 |
| `js/ai.js` | 图像处理、诗词生成、问答、海报算法（`window.AI`） | 直接操作页面 DOM |
| `js/app.js` | DOM 绑定、事件、渲染、模块编排、启动 | 内容文案（应放 `data.js`） |
| `scripts/` | 本地开发辅助脚本 | 运行时代码 |
| `docs/` | 说明文档 | 代码 |

**依赖方向单向**：`app.js → ai.js / scene.js / data.js`，`ai.js → data.js`。下层不得反向引用上层，也不要跨文件直接改别人的 DOM 节点。

---

## 2. 通用格式（见 `.editorconfig`）

- UTF-8 编码、LF 换行、文件末尾保留一个空行、行尾不留多余空格。
- 缩进统一 2 个空格，不用 Tab。
- 所有源文件与文档使用中文注释；变量与函数名用英文。
- 每行尽量控制在 120 字符内；长文案允许超长，但不要塞进逻辑判断里。

---

## 3. JavaScript

- 每个文件头部有块注释，说明**文件职责**；文件内用统一的分节注释划出逻辑区块：

  ```js
  /* ===========================================================
     文件职责（一两句话）
     =========================================================== */
  ```

  ```js
  /* =========================================================
     3. 秋序时间轴
     ========================================================= */
  ```

- 浏览器侧文件用 IIFE 包裹并加 `'use strict'`，避免污染全局；确需跨文件共享时只允许挂载 `window.DATA` / `window.Scene` / `window.AI` 三个命名空间。
- 优先 `const`，需要重新赋值才用 `let`；不使用 `var`。
- 函数、变量命名用 `camelCase`；常量用全大写下划线（如 `LEAF_COLORS`、`PAPER`）；DOM 查询统一用文件内的 `$` / `$$` 辅助函数。
- 注释写「为什么」，不写「这行在做什么」。算法里的非直觉处理（例如明度映射为何不用逐通道量化、七绝第三句为何必须仄收）必须留注释。
- 异步统一用 `Promise`，回调里要有失败分支；导出图片等可能失败的操作要给用户可见提示。
- 不使用外部库；不引入 `eval`、不拼接 HTML 后 `innerHTML` 注入用户输入内容。
- 文案里的数量、名称必须与数据层一致，改数据结构时同步更新注释与文档（曾经出现过注释写「六韵部」而实际只有 4 个韵部的问题，已修正）。

---

## 4. CSS

- 颜色、字号、间距等基础值集中在 `:root` 设计令牌中，组件里只引用变量，不散落魔法数值。
- 类名采用「块-元素」小写连字符风格（如 `.sec-head`、`.st-tab`、`.ps-note`），状态用 `.is-active` 一类前缀，不用 ID 做样式选择器。
- 尽量避免 `!important`；确需覆盖时写明原因。
- 动画优先 `transform` / `opacity`；提供 `prefers-reduced-motion` 或等效的降级思路。
- 响应式断点放在文件末尾集中维护，方便评审定位。

---

## 5. HTML

- 用语义标签（`header` / `nav` / `main` / `section` / `footer`），每个 `section` 有唯一 `id` 供锚点导航。
- 装饰性元素加 `aria-hidden="true"`，可交互控件有可读名称（`aria-label` 或文本）。
- 不写内联 `style`、不写内联 `onclick`；脚本放在 `</body>` 前，按依赖顺序同步加载。
- 不引入任何外部 URL（CDN / 字体 / 图片 / 统计脚本）。

## 6. Git 提交规范

提交信息格式：`<type>(<scope>): <中文简述>`，简述写清「做了什么」，必要时在正文补「为什么」。

| type | 用途 |
| --- | --- |
| `feat` | 新增功能或模块 |
| `fix` | 修复缺陷 |
| `refactor` | 结构或文案调整，不改变功能 |
| `docs` | 文档 |
| `chore` | 工程配置、部署、忽略规则 |
| `test` | 验证相关 |

scope 常用：`data` / `style` / `scene` / `ai` / `app` / `page` / `deploy` / `docs`。

约定：一个提交只做一件可说明的事；不提交 `.env`、编辑器配置、系统文件、构建产物；提交前跑 `npm run check`。仓库分阶段提交历史与各轮改版说明见 [开发日志.md](开发日志.md)。

---

## 7. 提交前自查

```bash
npm run check                                      # JS 语法
grep -RnoE 'https?://' index.html css js | grep -v 'www.w3.org/2000/svg'   # 零外链
git status --short                                 # 确认无临时文件混入
```

浏览器侧再确认：控制台 0 报错；上传 → 迁移 → 下载、作诗 → 海报导出、问答、文物弹窗、手机宽度响应式均正常。
